## 二、任务单契约块规范（R0/R1 强制，R2 建议）

派单（`kanban_create`）时 body 必须附：

```
【契约块】
- input_contract: <上游产物/数据文件+路径；独立任务写"独立任务">
- acceptance_criteria: （机判项，验收方逐条执行，任一 FAIL → kanban_request_changes 打回）
  1. `python -m py_compile <新文件>` → exit=0
  2. `python check_backtest_sanity.py` → PASS
  3. `pytest tests/test_<模块>.py` → 全绿
- output_contract: <产物文件路径 + 最低字段：改动+一手证据+回归+回滚点+未验证项>
- retry_budget: 2        # 显式声明（kanban_create 的 max_retries 参数）
- degradation_path: <失败时先降级什么再 block，查 §3.3 表>
```

机器判据（`scripts/check_task_contract.py`，立规时刻 RULE_EPOCH=2026-10-20，不溯及既往）：
- **C1** body 含「【契约块】」标记
- **C2** acceptance_criteria 段 ≥1 条机判行（反引号命令/路径 + PASS/exit/全绿/数值断言）
- **C3** output_contract 段非空（不得为"无"）
- **C4** retry_budget 显式声明（N 或 NULL=接受默认）
- **C5** R0 任务（标题/body 命中：回测引擎|评分函数|成交模型|数据合并|risk_rules|trade_log|holdings|因子权重|cron 巡检）→ degradation_path 段非空

## 三、治理规则

### 3.1 重试预算声明（修 G-1）
| 任务类 | 创建时 `max_retries` |
|---|---|
| R0 高危 | 2（3rd 次自动进 gave_up → 转人工，防 09-21 式连环 crash） |
| 数据拉取类 | 3（非交易时段不可达属常态） |
| 评审类 | 1（评审打回走 kanban_request_changes 重入队，不计 crash 预算） |

现状 `max_retries` 0/280 全走 dispatcher 默认 —— 新单必须显式声明；旧在途单挂技术债台账不追。

### 3.2 降级路径表（修 G-2，失败后先降级、再 block，顺序执行）
| 任务类 | 降级路径（block 前按序） |
|---|---|
| R0 回测/评分 | ① 截短窗口复现（单股/单日）→ ② `check_backtest_sanity.py` → ③ 20日快速版（**标"未全量确认"，合入前必须 132d 全量，铁律4**） |
| R1 脚本 | ① 最小样本重跑（1只/1日）→ ② 输出与改前对照留痕 |
| 数据拉取 | ① 开盘后重试 → ② 用缓存 + WARN 标记（跳过不造数据，参照 TEAM-COMMS §2.3） |
| 模型/provider | fallback_providers 链（config.yaml AGNES 双 key 已在位）→ 仍败 → block kind=transient |
| 降级仍败 | block + kind（needs_input/capability）+ 失败一手证据 ≥2 条 |

### 3.3 完成信号机判（修 G-3）
验收（总管）= 逐条跑 acceptance_criteria → 全 PASS 才 `kanban_complete`；任一 FAIL → `kanban_request_changes`（附具体整改项，任务重入队，不计 crash 预算）。`goal_mode` 任务的 judge 以同一清单为判据，不再"感觉做完"。
