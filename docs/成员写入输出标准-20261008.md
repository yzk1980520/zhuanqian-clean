### 1.2 唯一合法写口四原则（R1 铁律可执行化；2026-10-16 增第 4 条，v1.1）

1. **原子性**：一切 `data/**.json` 落盘走 `atomic_json`（tmp+os.replace+fsync）；`open(path,'w')` 直写 data/ 视为 P1 缺陷（gate_check.py 已挂账）。
2. **read-back 断言**：每次写后**必须**重读并断言"改动字段=预期值 + 未改字段=原值"。断言不通过 = 本次写失败，回滚 tmp 并上报。无 read-back 的写 = 未验收。
3. **异常 loud**：写路径 `except` 不得静默吞（SOUL#9 / R2 铁律）。`except: 默认值` = P0 缺陷；`except Exception: print(⚠️)后继续` 在**闸门/同步类路径** = 假绿，必须 loud fail + per-item 隔离。
4. **回授断言注册**（v2.3 §2.9 铁律，老大 2026-10-16 拍板）：新建写侧动作（cron 事件/台账/消息/文档条目/任务单结论）必须同时登记读侧消费断言——消费方 + 消费周期 + 失败告警路径，未注册 = 未完成的闭环，不得宣称"已闭环/已生效/已送达/已监控"；老五评审 checklist 增"回授断言在位"项，缺项即打回。豁免：P0 实时告警类先行直发、24h 内补断言。

### 1.2.1 写口选择判据（K55 §六 指令，R4c 系列复盘沉淀）

改裸 `open('w')` 为原子写时，`atomic_json` 两个写口按**语义**选，禁一律套 `update_json`：

| 文件语义 | 写口 | 理由 |
|---|---|---|
| **台账类**（有读旧+追加/合并语义：trade_log/holdings/registry/含 append/mutate 的 review_status）| `atomic_json.update_json`（FileLock + 读旧 + mutator + 全量写）| 跨进程读-改-写要锁；mutator 读旧再改是**本来就要读旧**的语义 |
| **可再生覆盖类**（无条件全量覆盖、不读旧文件：数据池派生/标记/研究 artifact/重生成文件）| `atomic_json.atomic_dump`（tmp+fsync+replace+目录fsync，零读侧）| 全量替换语义 100% 等同原裸 `open('w')`；若误用 `update_json` 会引入"旧文件损坏→RuntimeError 拒写"新副作用（= 行为漂移，R4b 类） |

**判据落地检查（每项改口必过，同"补 2 全量替换语义确认"）**：改后断言 ① 全量替换（旧 STALE 字段不残留）② 与原始 `open('w')+json.dump` 产出一致（normalize 后相等）③ 无 tmp 残留。

**已应用实例**：R4c #1 holdings=台账→update_json；R4c #2 audit_trigger / #3 akshare_stock_pool / #4 industry_mapping / #6 factor_correlation_matrix=可再生覆盖→atomic_dump。

### 1.3 数据卫生红线（K45 #3 口径修正落档）

- **chg5 = 反向**（registry ic_mean=−0.0262，负 IC 正向因子）；**chg10 = 弱-死**（ic_mean=+0.0185 < 0.03 门禁线，**不是反向**）。
- 任何文档/备注/IC 记录对 chg10 写成"IC 反向失效"= 证据卫生缺陷，评审打回。
- `ic_mean=None`（Q1 隔离态）是合法值：**禁洗成 0.0**、禁当死数据删（K44 D2 判据）。
- 一手证据（回测/convexity 校验文件）损坏时：**重生成 > 标损坏保留 > 删除**；删除须 D2 安全流程（.trash + md5 + 变更日志 + 报待删清单）。
- **config 禁塞 schema 外键（K51 §六 红线）**：`config.json.factor_weights` **只允许 schema 内键**（现役因子 key + `LOWER_SHADOW`/`UPPER_SHADOW`）；任何备注/口径/说明**进 CHANGELOG 或 registry，禁止写进 config**。违反 = 触发漂移守卫假漂移（报"未知 key"）= 污染实盘状态判读。事故先例：#3 执行首版误把 `chg5_note/chg10_note/#3_rationale/#3_at` 4 个 schema 外键塞进 `factor_weights` → 假漂移 → 已移除（教训=实盘写口严守 schema 边界）。

## 二、成员输出标准（报告/回执/登记最低字段）

### 2.1 最低字段（缺一即打回）

| 场景 | 必含字段 |
|---|---|
| 修复回执 | 改了什么（diff/文件:行）/ 一手证据（命令+输出+时间戳）/ 回归状态（pytest 行）/ 回滚点（.bak/.trash 路径）/ 未验证项清单（明说"未验证"） |
| 评审结论 | 结论（放行/打回）/ 逐条断言与证据 / P0/P1/P2 分级 / 打回项的复验方式 |
| 因子登记 | factor_id / 定义源(registry desc) / 实现函数(文件:行) / IC 数值+窗口+方向 / 权重去向(active/pending + 是否进实盘) —— **四源缺一 = 登记无效**（因子四源术语） |
| 验收报告 | 每个"✅"挂一手证据；写不出证据的项**如实标"未验证"**，禁止打勾（SOUL 准则 5） |

### 2.2 禁止表述（出现即视为违规输出）

- "已修复 / 已归一 / 已解决" 用于**未复核**项 → 必须写"已改，回归未跑/未验"
- "结果验证通过" 但数字来自**引擎变更前的 commit** → 必须声明引擎 commit（SOUL 准则 7）
- "IC 反向" 用于未查原始 IC 数据的因子（记忆/引用不算证据）→ 必须附 IC 数值+文件+时间戳
- "历史绿所以现在绿" → 必须重跑，历史结果不得作新引擎验证（SOUL 准则 7）
- 静默翻转（None→0.0、异常→默认值、数据方向反转）→ 一律 loud fail + 上报

### 2.3 证据链字段（AGENTS §6.2 可执行化）

每个进化变更的登记 JSON 必含 10 字段：决策ID / 时间戳 / 提案来源 / 数据窗口 / 含退市股标记 / 前后指标对照 / 悲观场景损失 / 论点对称性 / 失效触发条件 / 评审人 + 验收结论。缺字段 = 不得合入。

## 三、入库≠实盘 边界（K45 重申，D1 口径 A）

- 双管线 = **分阶段打通**（长期打通），**禁止**写"永久隔离"：
  - 阶段 A（当前）：研究管线（registry/PCA）与 S3 实盘（config factor_weights）隔离运行，文档标注目标态；
  - 阶段 B：registry 成唯一真源，S3 侧改读 registry（另开任务单）；
  - 阶段 C：研究因子经评审映射进 config.json factor_weights（另开任务单）。
- **硬红线（永不取消）**：`gate=pass` ≠ 可进实盘。任何阶段进实盘 = 新任务单 + 老五评审 + 回滚方案。
- 研究因子**不得**自动流入实盘权重；`scripts/factor_registry.py` 旧版 `sync_to_config()` 绕 atomic_json 直写 config 的行为随 R3 归档作废（2026-10-09，见 CHANGELOG R3 条目）。
