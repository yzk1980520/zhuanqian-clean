### 1.2 原解析器为什么会读出 0 个

旧代码"格式2"分支按 `{因子名: {ic_mean, status}}` 的 **dict** 解析，而权威源
`factors` 是 **list**。对 list 执行 `.items()` 会直接抛 `AttributeError`；
即便不抛，`for factor, data in ic_data.items()` 遍历的是顶层
`{last_date, freshness_days, ...}` 的 5 个键，`data` 全是非 dict 标量，
`isinstance(data, dict)` 全 False → 循环体零次执行 → 有效因子 0 个。
实测旧逻辑对权威源确实得 0（旧门禁之所以显示 12，是因为它读的是**另一个文件**
`data/factor_ic.json` 的 `valid_factors` 段）。

## 二、因子闭环（IC → 建议 → 老大拍板 → 才写）

### 2.1 打通了什么

改造前：`evolution_loop.py` 全文 grep `weight` / `factor_weights` **零命中**，
IC → 权重更新确实没有任何代码路径。

改造后新增三环 + 一个总入口：

| 环 | 落点 | 作用 |
|---|---|---|
| 第1环 IC | `data/factor_ic/factor_ic_latest.json` | 权威源（已换） |
| 第2环 建议 | `scripts/factor_weight_proposal.py` + `evolution_loop.propose_factor_weight_adjustment()` | **只读**权重文件，产出 proposal |
| 第3环 拍板 | `evolution_loop.weight_update_seam()` → `check_production_gates()` | 老大 `boss_release` 未拍板即阻断 |
| 第4环 执行 | `scripts/apply_factor_weight_proposal.py` | 全仓**唯一**写 `factor_weights.json` 的脚本，需批准件 |

`evolution_loop.py`（备份 `evolution_loop.py.bak_20261017_w1`）新增三个函数，
沿用该文件既有的依赖注入风格：`propose_factor_weight_adjustment(proposal_fn=None)` /
`weight_update_seam(proposal, gates_fn, apply_fn)` /

**红线钉死在代码里**：`apply_fn` 默认 `None` —— 不显式注入写口就永远写不了。
第4环的写口只在独立的 apply 脚本里，且必须过批准件。

### 2.2 建议规则（保守，不臆造量级）

| action | 触发 | 处置 |
|---|---|---|
| `KEEP` | 权威源 `status=='valid'` | 保留现权重 |
| `ZERO` | 权威源 `status=='dead'` | 建议停用置 0 |
| `UNCOVERED` | 权重表有但权威源没算 IC | **不动**，列入"待补 IC"清单 |
| `OBSERVE` | 权威源 valid 但权重表没有 | 纳入观察，权重 0（不自动赋权） |

任一因子 `|变化|/|原值| > 20%`（阈值取自 `config/factor_thresholds.json`
`权重变化阈值.change_pct`）→ `summary.needs_manual_review = True`。

另外：匹配用**大小写不敏感**（权重表 `rsi14` ↔ IC 源 `RSI14`），
实跑发现确实能匹配上 `rsi14`/`RSI14`、`vol_shrink20`/`VOL_SHRINK20`、
`chg5`、`chg10`、`alpha16_fix`、`vol_ratio` —— 四套"活跃因子清单"并非完全不相交，
大小写归一化后有 6 个交集。

### 2.3 proposal 脚本红线自检

`scripts/factor_weight_proposal.py` 内置 `_assert_no_weight_write()`：
扫描本文件源码，凡提到 `factor_weights.json` / `WEIGHTS` 的代码行，
一旦出现 `'w'`/`"w"`/`write_text`/`replace(`/`unlink(` 等写口 token 立刻抛
`AssertionError`。即：谁想在建议脚本里加写口，自检当场炸。
