## 三、A12 升级：从「1 个载体」到「4 个关键载体全覆盖」

**为什么要改**：原 `check_a12` 只查 `Zhuanqian_ClosedLoopHealth` 一个任务。
改造后即便另外三个载体被删、或被改回 `.bat` 直调（弹窗），体检器仍报 **A12 PASS**
—— 这正是 MEMORY 里记过 ≥11 次的「存在性断言发现不了执行层变化」。

改动（`scripts/closedloop_health.py`）：
- 新增 `CARRIER_SPECS` 清单（4 项：ClosedLoopHealth / CalendarRefresh / WeeklyIC / DailyReview），
  头部写「严禁删条目、降为查一个就算过」。
- `check_a12` 遍历清单，每个载体查三层：入口 .bat 存在 → `run_path_hidden.vbs` 存在 →
  任务已注册且 Command 走 wscript。
- 聚合：任一 FAIL ⇒ 整体 FAIL；无 FAIL 有 PARTIAL ⇒ PARTIAL（未注册需提权，不判死）。
- 显示名 `A12_体检器调度载体` → `A12_关键调度载体`（同步改守卫 G9 的字符串，判据未放宽）。

**降级自证（tempfile 构造，不碰生产文件）**：

### 选择题（铁律2）—— 老大已于 2026-10-20 拍板：**A 不动**

**Q：WeeklyIC 的 StartBoundary（周三）与 Days=[Sunday] 不一致，要不要重注册对齐？**

| 选项 | 做法 | 后果 |
|---|---|---|
| **A（老大已选）不动** | 保持现状 | `DaysOfWeek=Sunday + WeeksInterval=1` 保证每周日 04:30 必跑；最坏 10-21 周三加跑一次（检测脚本幂等、只读源数据，无害）。省一次提权操作 |
| B 重注册对齐 | 老大再跑一次 `register_weeklyic_task.ps1 -Force`（StartBoundary 改 2026-10-25 周日） | 触发语义严格无歧义；代价=多一次提权操作，且改动期间任务短暂解绑 |

**裁定 A 的理由**：不一致只影响"首次可能落在哪天"，不影响"每周日必跑"这一事实；
真正的风险（不跑/漏跑）已由 A12 的注册态+静默三层和 A5 心跳覆盖。

**⚠️ 后人勿再当缺陷报**：这是**已知且已裁定**项，不是配置错误。若将来有人看到
`StartBoundary=2026-10-21` 与 `Days=[Sunday]` 不一致而提单，直接引本节结案。

**留下的观察点（唯一需要事后确认的事实）**：若 2026-10-21（周三）04:30 真的加跑了一次，
`data/weekly_ic.log` 会多一条 10-21 记录——**出现即无害，不必处理**；
若 10-25（周日）04:30 之后日志无新增，才说明调度器没按 Sunday 触发，那时才需要按 B 重注册。
⇒ 验证时点：**2026-10-25 之后**查一次 `data/weekly_ic.log`。
