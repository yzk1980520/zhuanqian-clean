## 2. 1.27e9 是什么

**不是常量、不是溢出、不是单位/量纲错误，是 float32 → uint32 的"类型误读"**：
`amount` 被写成了 **IEEE-754 单精度浮点数的位模式整数值**。

**为什么呈现"≈1.27e9 近常数、日间 CV<1.2%"：**

TDX `.day` 第 6 字段是 float32。真值成交额典型在 1e8 量级，其指数域 `exp` = 26 或 27：
```
exp=26 → 26+127=153 → 153 << 23 = 1 283 457 024
exp=27 → 27+127=154 → 154 << 23 = 1 291 845 632
尾数只占低 23 位（≤ 8 388 607），相对 1.28e9 只有 0.65%
```
→ 指数不变时金额只在 ±0.65% 内抖动，**日间变异系数必然 <1%**，完全复现主理人观察到的"近常数、CV<1.2%"。
坏值跨股票的区间（本人实测 1.166e9 ~ 1.366e9）正好对应真值跨 2 的幂次时指数域跳变。

**主理人给的实锤样例，本人复核一致：**
```
sz301683 2026-04-13  库值 amount = 1309031141
位模式反变换 → struct.unpack('<f', struct.pack('<I', 1309031141))[0] = 563001664.0 = 5.63 亿
主理人按 volume×close 估算 = 4760202 × 119.44 ≈ 5.68 亿   ✅ 吻合（VWAP 与收盘价的正常差异）
```

**"换算系数"的答案：不存在乘除系数，是位重解释，且严格无损：**
```python
amount_true = struct.unpack('<f', struct.pack('<I', int(amount_bad)))[0]
```
本人实测：对 5 只坏股的全部 6623 条记录做反变换，与 TDX 源逐一比对，**6623/6623 完全一致（误差 <1 元）**。
→ 这意味着**修复不需要 TDX、不需要网络、不损失任何精度**。

### 规律

- **不沿时间**：坏文件是**整文件被覆写**，所以 2017–2026 全部年份、每一条记录都坏（不是"某段时间坏"）。主理人观察到"跨全部年份都坏"与此一致。
- **沿批次**：坏 = 被 `tdx_to_json_converter.py` 跑到的那批；好 = 被 `bulk_refresh_history_daily.py` 重写的那批 / 被外部源补的那批。好坏**来自同一源（都是 TDX）**，差别只在解析器。
- **坏文件内坏记录率 = 100%**（不是 62.67%）：4502/4502 逐条比对 0 例外。
- **为什么 sz\* 全军覆没**：10-15 那次正确的 `bulk_refresh_history_daily.py` 按 `sorted(all_codes)` 处理，**只做到 `sh900928` 就停了**（本人实测好批次 max=sh900928、min=sh000001），没轮到 `sz*`；另外它对"无缺失日期"的文件直接跳过（`:110-112`），所以可转债 `sh11xxxx` 也没被修。
- **volume / OHLC 完全干净**：与 TDX 逐条比对 volume 完全一致（本人实测 sz002457 等 5 只，volume 100% 相等），因为 TDX 里只有 amount 是 float32，其余全是 uint32——**这正好解释了"为什么只有 amount 坏"**。

- 主理人："坏股 66.0%、坏记录率 62.67%"（引用主理人实测）
