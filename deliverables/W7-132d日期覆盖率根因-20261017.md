## 一、结论（先给答案）

1. **N 解出来了，但假设被证伪。** 存在 N ∈ **[1674, 1676]** 使得「n_valid ≥ N」的日期数恰好 = 85。但用该规则重跑后，`chg5`/`chg10`/`momentum_20` **仍然全为负、没有翻正**，符号一致率反而从 21/28 **降到 20/28**。
2. **「112 → 109 → 85」无法用单一 per-date 最小有效股票数阈值解释。** 而且更进一步：**「日期数 = 85」这个约束本身就不携带信息**——随机抽 85 个日期跑 3000 次，符号一致率落在 16~23（中位数 21），pearson 落在 -0.098 ~ +0.513（中位数 +0.189）。当前基线的 21/28、r≈0.23 完全在随机区间内。
3. **真正的分歧变量不是日期，是截面成分（股票清单）。** 动量族符号随截面规模翻转、随日期筛选几乎不动：300 股这一档能让 `chg5`/`chg10`/`momentum_20` **全部翻正并与基线同号**。
4. **顺带查出一个更严重的问题：基线那 112 个「132d 目标日期」根本不是 132 个交易日**，跨了 5 年（2021-10-11 ~ 2026-10-14）。引擎自推的日历才是真 132 个连续交易日（2026-03-23 ~ 2026-09-30）。两者交集只有 77 个日期。
5. **判断：新引擎更可信。** 理由见第五节。

### B. 反解阈值 N

扫描 N ∈ [0, 1800]：

| 目标计数 | 对应 N |
|---|---|
| 112 | N = 0 |
| **107** | **N ∈ [5, 1426]** |
| 86 | N = 1673 |
| **85** | **N ∈ [1674, 1676]** |
| 84 | N = 1677 |

**N 解出来了：1674 / 1675 / 1676。**

但必须同时报告下面这条，否则这个"解"会被误读成证据：

> **该假设不可证伪。** n_valid 在 [1426, 1761] 上是连续分布的，扫描得到的"可达计数"有 **75 个不同取值（0~112）**。也就是说，任意 1~107 之间的日期数都能由某个 N 生成。命中 85 是单调性的必然结果，**不构成任何证据**。

再看 N=1674 到底筛掉了谁（这才是判据）：

- 保留 85 日：2025-07-15 ~ 2026-09-29（**81 个 2026 年 + 4 个 2025 年**）
- 丢弃 27 日：2021-10-11、2024-08-09、**20 个 2025 年日期**、加末尾 5 个无前瞻收益日
- 被剔的 22 个真实截面日，n_valid 在 **1426 ~ 1673** 之间，是 `MIN_SECTION=50` 的 **28 ~ 33 倍**

→ 所以 N≈1675 实质上是**「只要 2026 年」的时间过滤器**，不是样本量过滤器。一个"最小有效股票数"阈值不会长成这样（正常人会写 10/20/30/50/100/200）。

**用 N=1674 重跑（85 日）的结果：**

| 因子 | 基线 | N=1674 重跑 | 是否翻正 |
|---|---|---|---|
| chg5 | +0.0397 | **-0.0101** | ❌ 仍负 |
| chg10 | +0.0539 | **-0.0125** | ❌ 仍负 |
| momentum_20 | +0.0382 | **-0.0335** | ❌ 仍负 |

| 配置 | 日期数 | 符号一致 | pearson |
|---|---|---|---|
| 基线日历 align=1（全量） | 107 | **21/28** | +0.1942 |
| 基线日历 align=1 + N=1674 | 85 | **20/28** | +0.2132 |

**动量族没有翻正，符号一致率反而下降 1 个。假设证伪。**

附：N 全扫描下符号一致率始终在 **19~21/28** 之间徘徊（N 从 0 扫到 1713，日期数从 107 降到 60），**没有任何一个 N 能让动量族翻正**。

### C. 交叉验证与对照实验

**（1）随机 85 日对照（3000 次抽样）——决定性的一条**

| 指标 | min | p05 | p50 | p95 | max |

当前基线的 **21/28、r≈0.23 正好坐在随机分布的中位数上**。
→ **「85 个日期」这个约束不携带任何可辨识的信息。** 想靠挑 85 个日期把 28/28 对上，等价于抛硬币。

**（2）连续 85 日滑窗（23 个窗口）**

存在单调趋势：**越剔除最近的日期，相关系数越高（+0.19 → +0.47）**，说明分歧主要集中在最近 ~22 个截面日（2026-07 之后）。

但我明确拒绝把这个当成答案：**最早 85 日的 22/28、r=0.4692 仍然落在随机 3000 次的范围内（符号 max 23、r max 0.513）**。拿它去声称"基线用了最早 85 日"，就是典型的挑样本。

### D. 顺带查出：基线那 112 个「132d 日期」名不副实

| | 基线 112 日 | 引擎自推日历 |
|---|---|---|
| 日期数 | 112 | **132** |
| 范围 | 2021-10-11 ~ 2026-10-14 | **2026-03-23 ~ 2026-09-30** |
| 年份分布 | 2021:1 / 2024:1 / 2025:24 / 2026:86 | 全部 2026 |
| 有 IC 的日期 | 109 | 131 |

两者**交集仅 77 个日期**；54 个仅自推日历有，35 个仅基线有。

引擎在不喂 `--dates-file` 时，自己推出来的是 **132 个连续交易日（2026-03-23 ~ 2026-09-30），131 个有 IC** —— 这才是 `window_days=132` 该有的样子。

**新引擎之所以"复现"了那 112 个日期，是因为被 `--dates-file data/factor_ic/_w1_target_dates.json` 强行灌了基线的日期清单。** 这不是复现，是继承。

自推日历（131 日）与基线对账：符号一致 **22/28**，pearson **+0.101**。也没对上 28/28，但它至少是一个自洽的 132 日窗口。

## 四、我的判断：哪一边更可信

**新引擎更可信。不是"都有可能"，是明确偏向新引擎。** 四条理由按权重排序：

**1. 可复现性 + 知道自己丢了什么（决定性）**
新引擎 112 → 107 丢的 5 个日期，**100% 可归因**（前瞻窗口超出数据末端），并且逐日留证在 `_w1_datediag.json` 里，任何第三方能重放、能挑错。
基线 112 → 109 → 85，中间丢的 24 个日期**没有任何记录、没有任何规则描述、生产者脚本从未入库**。一个说不清自己丢了哪些日期的引擎，其产出在方法论上就是不可审计的。

**2. 基线的隐含规则经检验表现得像随机**
这是本次最硬的一条：随机抽 85 个日期跑 3000 次，符号一致率中位数就是 21/28。基线当前的 21/28 恰好坐在中位数上。也就是说，**"85"这个数字里不存在可被辨识的规则信息**。反过来说，基线那 28/28 的一致性建立在一个无法描述、无法重建、也无法证伪的日期子集上——这本身就应该被质疑。

**3. 基线自己对不上自己的标签**
基线自称 `window_days=132`，但它那 112 个日期跨了 5 年（2021-10-11 ~ 2026-10-14），2021 年 1 个、2024 年 1 个。这不是 132 个交易日。新引擎自推的日历才是真 132 个连续交易日。**一个连自己的窗口定义都对不上的基线，没有资格当复现的目标。**

**4. 但我也明确说：新引擎"对了"这件事没有被证明**
新引擎同样没对上 28/28。只是"对不上"的原因，现在有实测证据指向**截面成分（股票清单）**而非日期——300 股这一档能让动量族三个因子全部翻正、与基线同号，而所有日期维度的筛选都做不到。基线用的股票清单从未入库，这才是真正卡住的那一步。

> 一句话：**该被质疑的是基线。新引擎的问题（对不上 28/28）是可定位、可继续查的技术问题；基线的问题（不可审计、口径自相矛盾）是方法论问题，而且它现在正被当作生产门禁的权威源。**
