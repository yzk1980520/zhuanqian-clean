### 为什么主源选腾讯，不选新浪

1. **腾讯带 `amount`（成交额）**，`tdx_indicators.py:265 / :724` 的因子要用。新浪只有 `volume`，没有 `amount`；而 `amount` 无法由 OHLCV 反推 —— 硬算就是伪造。
2. **腾讯与 TDX 完全一致**（这是选它的决定性理由）：

```
校验标的 sh600000（浦发银行），2000 根，2018-07-17 ~ 2026-10-16 全量比对
  volume: 本地(TDX) / (腾讯手数×100) = 中位数 1.000000  min 1.0000  max 1.0000
  amount: 本地(TDX) / (腾讯万元×1e4) = 中位数 1.000000  min 1.0000  max 1.0000
  OHLC   逐日完全相同（腾讯用 fq 参数留空 = 不复权，与 TDX .day 同口径）

示例（2026-10-16）：
  腾讯  o=9.60 c=9.73 h=9.79 l=9.53 vol=922942手 amt=89616.08万
  TDX   o=9.60 c=9.73 h=9.79 l=9.53 vol=92294208  amt=896160832
```
3. **腾讯单只上限 2000 根**（实测 2000 ✓ / 2048 ✗ / 2500 ✗ → `param error`）。够用，理由见 §四。

## 五、一个必须让老大知道的发现：0 根空壳其实是 132 只，不是 76 只

`157 = 15 + 66 + 0 + 76` 里的 **66 只 ST/*ST 剔除**中，有 **56 只同样是 0 根空壳**（只是因为回测器先过 ST 过滤，它们被计进 `st_skipped` 而不是 `empty`）：

```
ST/*ST 剔除共 66 只
  其中 0 根（也是空壳）          : 56
  其中 1~29 根                   :  0
  其中 >=30 根（有数据但被规则剔除）: 10
→ 157 只独家票里真正的"文件里 0 根"总计 = 76(非ST) + 56(ST) = 132
```

**当前不影响回测结论**（这 56 只按 `is_st_only` 规则本来就进不了池），但它是同一个 P1 缺口的另一半。是否一并补，已写入待拍板清单（议题 11-B）。
