## 二、问题 1（核心）：`is_tradable_code(code)` 不传 name → ST/退市过滤被短路（P0-A）

### 2.1 根因（改前实测确认）

`scripts/auto_live_pipeline.py` `run_stock_selection` 里：

```python
if not is_tradable_code(code):   # ← name 没传
    continue
```

而 `tdx_data.is_tradable_code(code, name="")` 的逻辑是：先 `should_include(code)`（板块白名单），
**然后才** `if name and is_st_stock(name): return False`。不传 name ⇒ 后半段整段被短路，
实际只排掉创业板/科创/北证/ETF，**ST 和退市股照样进评分**。

### 2.2 name 拿得到吗？—— 能，且覆盖率 100%（先报告再动手的结论）

任务卡要求「先确认 name 从哪里拿」。实测（`stock_names.json` + `data/history_daily` 全池实数）：

| 项 | 数 |
|---|---|
| `data/history_daily` 全量文件 | 9441 |
| 其中板块白名单内（`should_include`） | 3367 |
| 白名单池在 `stock_names.json` 名称表中的 | **3367（覆盖率 100%）** |
| 白名单池内 ST/退市（含"退"） | 303（其中含"退" 87） |

⇒ **不需要新造名称获取逻辑，也不需要联网批量抓名**：`tdx_data.load_name_cache()`
（`integrated_picker.py:35`、`backtest.py:423` 已在用的同一把钥匙）即可拿到全量名称，
键格式 `sh600000` 与 `history_daily` 文件名 stem 完全一致。池内未命中的代码 `name=""`，
退化为纯板块白名单（与改前行为一致，不误杀）。

### 2.3 修法（3 hunk，零新逻辑）

```python

# hunk 2 — 扫描循环前加载名称表（复用现有公共函数）
name_cache = load_name_cache()
print(f"名称表: {len(name_cache)} 条 (stock_names.json, ST/退市判定依据)")

# hunk 3 — 门禁调用传 name（原 :397-398）
if not is_tradable_code(code, name_cache.get(code, "")):
    continue
```

## 三、问题 2：`integrated_picker` 包/模块双实现

### 3.1 实测哪个在生效（`_diag_integrated_picker_shadow_20261019.py`，真实 import）

```

```

结论：**任何 `import integrated_picker` 拿到的都是包版**（包遮蔽模块）；根目录
`integrated_picker.py` 只有被当脚本直跑（`python integrated_picker.py`）时才生效。
且 `tdx_core.py:80` 有一个 `from integrated_picker.helpers import ...` 的传递依赖——
**任何 import tdx_core 的进程（含 auto_live_pipeline / daily_pick / 大部分 pytest）
都会加载包版**。包 `__init__.py` 的冻结警告（2026-09-25）自称「生产权威入口 = 根目录
integrated_picker.py」，但 import 侧活的一直是包版——这个认知差本身就在漂移。

### 3.2 ATR 判据分叉实测（行为级，不是读源码猜）

### 3.3 fail-loud 守卫（已落地）

在 `integrated_picker/filters.py` 末尾加 `_guard_atr_criterion_consistency()`：import 时对
本文件与根目录 `integrated_picker.py` 两处源码的 ATR 判据做文本级比对，不一致即
`warnings.warn("[fail-loud] integrated_picker ATR 判据分叉: ...")`。实测：

- `import tdx_core`（传递依赖路径）→ 告警触发 1 次，消息含两处判据原文与正确口径；
- pytest 运行时该告警进入 warnings summary（本次相关测试跑批可见）；
- 把包版改成百分比口径后（模拟合并）→ 告警自动消失，**不需要手工删守卫**；
- 为什么用告警不用 assert：`tdx_core` 在模块加载期传递依赖包，硬 raise 会瞬间放倒
  整条实盘链和大部分 pytest，把诊断变成事故；告警 fail-loud 且不制造次生灾害。

### 3.4 建议（哪份是活的 + 另一份怎么处置，等老大拍板）

**现状**：
- import 侧（含 tdx_core 传递依赖、测试、dojo_bridge 等库消费者）→ **包版是活的**；
