## 2. 重构原则（**可推翻 vs 不可推翻**，老大拍板硬线）

> **原则一句话：结构随便拆，契约不许动。重建后行为必须与基线逐字段一致。**

### 2.1 ✅ 可推翻（结构层，允许推倒重来，不必将就修补）

| 类别 | 允许的动作 |
|---|---|
| **目录结构、模块划分、文件命名** | 允许整体重组，不必保留旧路径 |
| **重复实现** | 只保留**一个权威载体**，其余一律删——**不要兼容层、不要适配层** |
| **内部接口形式**（函数签名、模块间调用方式） | 允许重设计 |
| **22 个计划任务的调度方式** | 允许推倒重建为统一调度 |
| **告警链路设计** | 允许重设计（前提是 §5 C5 唯一出口 + 契约冻结） |
| **已确认零调用方的死代码** | 直接删 |
| **逐行修补成本 > 重建成本 的组件** | 允许推倒重来 |

### 2.2 ❌ 绝不可推翻（契约层/红线，**重建也不许动**）

| 类别 | 冻结内容 |
|---|---|
| **契约数值** | S3 五档 `[(6,0.15),(10,0.05),(15,0.07),(25,0.09),(999,0.12)]`；硬止损 10%（含 `STRATEGY_STOP_LOSS_PCT` dict + `MARKET_STOP_ADJUST` 系数表**两张表**）；120 交易日；追高 4% |
| **策略语义** | 移动止盈吃大波段、全仓 1 只、本金安全第一 |
| **数据边界** | 数据不出本机 |
| **回测判据** | 全量 132 日为准、**必须含退市股** |
| **实盘数据** | `holdings.json` / `trade_log.json` 总管独占写 |

### 2.3 推翻重建的附加约束（**重建也要有护栏**）

1. **重建不得豁免 G1–G5**：重建前同样要回滚点、重建后同样要全量回归 + 132 日比对
2. **重建不得豁免 B-1**：无回归网时不得重建
3. **禁止兼容层/适配层**：重复实现只留一个权威载体，调用方直接改指新载体（此约束同时解决外部系统自带的 4 个 adapter 冗余）
4. **行为等价是验收标准**：重建后必须通过 §10 的 B 类全部断言

### 2.4 推翻重建候选评估（需求分析师建议）

> 判据：**组件内嵌的领域价值越低（越接近纯管道），越适合推翻重建；内嵌策略语义越重，越应改造而非重建。**

| 候选 | 内嵌契约/语义 | 建议 | 理由 |
|---|---|---|---|
| **告警链路**（30 文件写队列 / 2 写口 / 契约漂移 2 例 / 静默 continue） | **无**（纯管道） | **✅ 推翻重建** | 修补需逐改 30 处；重建只需 1 个写口 + 1 个消费口。且它是不合理与阻塞的集中点 |
| 调度方式（22 任务 / 2 来源 / 3 看门狗） | 无 | ✅ 推翻重建 | 同上，并解 B-3 |
| 外部 27 独有模块中的 adapter + 过度设计层 | 无 | ✅ **不收编直接废** | 收进来等于把冗余搬进仓库，违反铁律1 |
| **`integrated_picker` 四代** | **重**（嵌选股语义 2557 行） | ❌ **改造不重建** | 重建会丢失内嵌的策略边界处理；且紧邻契约层 |
| **回测 5 件套** | 重（嵌 132 日判据与策略语义） | ❌ **改造不重建** | 分层依赖，且回测判据是契约的一部分 |
| `risk_rules.py` | **全部是契约** | ❌ 冻结不动 | 契约层 itself |

## 3. 项目概述

### 3.1 一句话定位
对现有 A股单票轮动选股系统做**结构/模块/接口/逻辑/回测/数据/系统**七维度的**瘦身式重构**：去重、收敛、删死代码、收编仓库外平行系统，使系统在**功能完全不回归**的前提下变得可维护、可运行、可验证。

### 3.2 目标用户
系统所有者（老大）一人 + 既有七人研发团队（老大/总管/老三/老五/老六/老四/牛马）。无外部用户。

### 3.3 核心价值
当前系统的真实痛点**不是功能不足，而是"说得不算数与删了不敢删"**：

1. **一套职责多份载体** → 改了 A 份，跑的是 B 份（实测：`integrated_picker` 有 4 代、`atomic_json` 有 2 份分叉实现）
2. **系统在说谎** → 门禁报 `gate_ok: True` 但 30 个测试在失败 `[实测]`；队列日志说"失败保留 0 条"但条目永久滞留 `[实测]`
3. **告警链形同虚设** → 22 个计划任务 100% 为"只使用交互方式" `[实测]`
4. **调度来源分裂** → 8 个任务从仓库外启动、13 个从仓库内启动 `[实测]`
5. **系统存在两套** → 仓库内 1 套 + 仓库外 `.quant-stock-picker` 1 套 `[实测]`

### 3.4 成功标准（可判定，见 §10 验收标准）
