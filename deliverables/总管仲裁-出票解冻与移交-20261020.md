### 2.2 深层矛盾（老六补充，总管核实成立）
`factor_gate.json` 自述 `factor_layer_enabled=false`（source=config.json，「因子层显式关闭，不参与打分，选股只走结构/执行性判据」），**但 `daily_pick.py:110` 只看 gate_passed、不看 factor_layer_enabled ⇒ 因子层根本没参与打分，门禁 FAIL 却能一票否决出票**。

**总管定性**：
- 方向 = **fail-safe（拦住不出票=保守）**，不是假绿 → **不判它 bug、不直接修**。
- 上下文：老大 10-17 已拍板 132d+status 严口径（首例 B 方案，1/8 红，「最严格，等于承认因子库只剩 1 个能打的」）→ 门禁红是老大**已知且接受**的状态。
- 但「因子层关闭时门禁是否仍一票否决出票」= **门禁语义变更 + 资金动作**（放开=让资金按无因子层逻辑出票）⇒ **超总管权限，归老大拍板**。

### 2.3 方案（规范六段，转老大）
- **A（推荐）维持 fail-safe 现状，Path B 继续拦**：不出一只无因子层票 → 结果：停摆保守但资金零风险；代价：出票要等因子库恢复到 ≥8 有效（132d status 口径）。
- B 放行 Path B（让出票走纯结构/执行性判据）：结果：出票恢复但=资金按「无因子层」逻辑下单，且属门禁语义变更；风险：因子层 alpha 未证（v5_final_ruling 结论「OOS 期 alpha 瓶颈在选股层」），资金动作依据弱。
- C 二选一临时开关（config `factor_layer_enabled` 决定是否让门禁一票否决）：结果：把矛盾显性化成可调契约，供老大定档；风险：新增契约面，需老五会签。

**推荐 A，理由**：① fail-safe 是资金安全的保守方向，总管风险厌恶原则优先本金；② B/C 均为资金动作/契约变更，须老大（+老五会签）拍板，总管不越权；③ A 下 Path A 解冻不连带放行 B，两条路解耦，各按各自证据走。
