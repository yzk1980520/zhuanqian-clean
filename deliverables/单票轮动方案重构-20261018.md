## 一句话结论

【围绕单票全仓 + 移动止盈止损，选股信号应该优化 **"三重屏障结局"**——即「先不被 −10% 硬止损（尤其跳空）打掉，再吃到移动止盈阶梯」这一**路径依赖结果**（可用 60~120 日 MFE 或 barrier 对数收益度量），**而不是未来 5 日终点收益**。

最致命的现状是：**评价周期与持仓周期差 7 倍（5 日 vs 实测均值 35.8 日），而代价是可量化的——即使给一个完美的 5 日收益预测器，它也只能兑现"理论最高可得收益"的 26.0%；同样完美的 120 日 MFE 预测器能兑现 98.9%。也就是说，74% 的可兑现收益被目标函数本身丢掉了，与因子质量无关。**】

## A. 评价目标重定义

### A-0 先把「盈利机制」钉死：移动止盈到底在吃什么

我对 `risk_rules.py` + `backtest_rotation.py` 逐行实读，确认实盘/回测的退出状态机是（优先级严格按代码顺序）：

| 步骤 | 位置 | 规则 |
|---|---|---|
| 高点更新 | `backtest_rotation.py:696-697` | `high = max(high, 收盘)` —— **移动止盈基准是「持仓期最高收盘」，不含盘中上影线**；初值 = 买入价（`:665`） |
| ① 硬止损（先判） | `:716-718` | 当日 `low <= entry×0.90` → 按 `min(止损价, 开盘价)` 成交；开盘已低于止损价记为「止损(跳空)」 |
| ② 移动止盈（else 分支） | `:733-741` | `pnl = (high/entry−1)×100` → `trailing_pct(pnl)` 选档 → `trail = high×(1−tp)` → 当日收盘 ≤ trail 则按收盘卖出 |
| ③ 时间止损 | `:743-745` | 持有 ≥120 交易日 → 按收盘卖出 |
| 跌停顺延 | `:752-765` | 卖出日封死跌停（≤−9.8%）→ 顺延，最多 3 日后投降按收盘卖 |

阶梯与选档（**`risk_rules.py:230` 原始值 + `backtest_rotation.py:274-283` 选档逻辑**）：

```
TREND_TP_LADDER["up"] = [(6,0.15), (10,0.05), (15,0.07), (25,0.09), (999,0.12)]
选档: for up_to, dd in ladder: if pnl < up_to: return dd     # 首个阈值 > 当前浮盈 的那档
```

⚠️ **更正主理人 brief 中的一处偏差**：主理人写「激活 10/15/25/∞，锁 5/7/9/12%」，实际是 **5 档**，首档为 `(6, 0.15)`：

| 峰值浮盈 pnl | 取到的回撤容忍 dd | 兑现的锁定价（= high×(1−dd)） |
|---|---|---|
| pnl < 6% | 0.15 | 不可达（见下） |
| 6% ≤ pnl < 10% | 0.05 | entry×1.007 ~ entry×1.045 |
| 10% ≤ pnl < 15% | 0.07 | entry×1.023 ~ entry×1.070 |
| 15% ≤ pnl < 25% | 0.09 | entry×1.047 ~ entry×1.138 |
| pnl ≥ 25% | 0.12 | ≥ entry×1.10 |

**「首档 `(6,0.15)` 不可达」是被代码和数据双重证明的**：因为 −10% 硬止损每天都先判且用盘中 `low`，而要触发 15% 回撤需要 `close ≤ 0.85×entry`，这必然先让 `low ≤ 0.90×entry` 触发止损。
**一手证据：TURN5 报告三个 run 共 116 笔交易，退出原因只有「回撤 5% / 7% / 9% / 12%」，「回撤 15%」一次都没出现过**（本轮从 `deliverables/qa_turn5_full.json` 重新统计确认）。

> 由此得到本次方案最重要的一条结构性认知：
> **单笔收益 ≈ f(持仓期最高收盘价的路径)，而不是 f(某个固定日期的终点价)。** 参与定价的两个量（选档输入 `pnl`、止盈线 `trail`）都只是 `high` 的函数，而 `high` 是路径最大值。

### A-1 五个候选目标的对比

| 候选 | 衡量什么 | 怎么算 | **与移动止盈机制对齐吗** | 计算成本 |
|---|---|---|---|---|
| **(a) 未来 N 日终点收益**（现状 N=5） | 持有 N 天后值多少 | `(close[t+N]/close[t]−1)`，`factor_ic_132d_refresh.py:580` | ❌ **严重不对齐**。实际兑现取决于路径最大值，终点收益只是路径上的一个点 | 极低 |
| **(b) 触发移动止盈阶梯的概率** | 能不能启动盈利机制 | `P(峰值浮盈 ≥ 6%) 且不在涨之前被止损` | ✅ 部分对齐（抓住了"激活"这一步），❌ 但**丢掉了"激活后吃多少"**，只看是否触发不分好坏 | 低 |
| **(c) 买入后最大有利偏移 MFE** | 波段幅度 | `max_{k≤N}(high_k/entry−1)`，其中 high 用持仓期最高收盘 | ✅ **高度对齐**：`TREND_TP_LADDER` 的选档输入正是它 | 低（一次滑动最大值） |
| **(d) 条件生存概率**（先不破硬止损） | 能不能活下来 | `P(未被 −10% 止损（含跳空）打掉)` | ✅ 对齐"本金安全第一"，❌ 但**单独用会选出不动的票** | 低 |
| **(e) 组合：先活下来，再吃波段** | 活下来之后能兑现多少 | **三重屏障标签 / barrier 对数收益** | ✅✅ **完全对齐**（定义上等价） | 低（见下实测） |

### A-2 择优结论：**推荐 (e)，形态为「三重屏障标签 + 对数收益」**

> **推荐目标 = `u = log(1 + Y_barrier)`**
> 其中 `Y_barrier` = 在**真实**三条屏障下模拟出的单笔收益率：
> - 上轨 = `TREND_TP_LADDER["up"]`（**复用** `backtest_rotation.py:274-283` 选档）
> - 下轨 = `entry × (1 − 0.10)`，跳空按开盘成交、跌停封板顺延 ≤3 日（**复用** `:716-765` 语义）
> - 竖轨 = 120 交易日（`TIME_STOP_TRADING_DAYS`）
>
> 即：**「`backtest_rotation` 已经在输出的那个 `exit_reason` 和 `pnl_pct`」就是标签本身。**

这正好是 López de Prado 的 Triple-Barrier Labeling 在本系统的自然形态——**不需要引入新概念，只需要把回测出口当成标签机**。

#### 三条由此确立的结论

**结论 1（回答主理人问题 1）：错配的代价 = 丢掉 74% 的可兑现收益。**
`forward_days=5` 下，即使预测器完美，也只捕获 26.0%。同样的完美预测器换成 120 日 MFE，捕获 98.9%。**这 3.8 倍的差距全部来自"问错了问题"，与数据质量、因子挖掘无关。**

**结论 2（意外收货，支撑结论 1 的自洽性）：终点收益类的最优 N = 35，而实测平均持仓是 35.8 天。**
两个**完全独立**的量撞击在同一个点上（引用 TURN5 报告：基线 S3 平均持仓 35.8 天；本轮实测：终点收益捕获率峰值出现在 N=35）。这不是巧合，而是再次证明：**当前 5 日是错的，正确量级是 ~35 日**——5 与 35 差 7 倍，与主理人说的 7 倍完全一致。

**结论 3（决定用 MFE/barrier 而非任何终点收益）：同一 horizon 下，MFE 在 N≥20 全面碾压终点收益。**
| horizon | 终点收益捕获 | MFE 捕获 |
|---|---|---|
| 5 日 | 26.0% | 21.5% |
| 10 日 | 39.6% | 36.8% |
| 20 日 | 51.0% | **54.4%** |
| 35 日 | 54.5% | **70.9%** |
| 60 日 | 46.4% | **86.5%** |
| 120 日 | 28.0% | **98.9%** |

交叉点约在 15~20 日：**短周期（≤10 日）内 MFE 与终点收益几乎等价且都很烂（21~40%）；长周期 MFE 单调上升至近 100%，终点收益反而掉下来。** 因为持有越久，路径形状越主导结果。

**秩相关侧证**（逐日 Spearman 均值，目标 vs 真实兑现 `Y`）：
- `IC(5日收益, Y)` = **+0.4622**
- `IC(MFE5, Y)` = +0.3490
- `IC(MFE20, Y)` = **+0.6351**

→ **MFE20 与真实兑现结果的相关性，比现行 5 日收益高 37%。**

#### 为什么用 `log(1+Y)` 而不是 `Y`

|<0xE2><0x80><0x8B>|<0xE2><0x80><0x8B>|
|---|---|
| 单笔算术均值 E[Y] | **+0.666%** |
| 单笔几何等值 E[log(1+Y)] | **−0.317%** |
| **波动拖累** | **+0.982 pp/笔** |
| 单笔 p1 / p5 / p99 | −16.51% / −10.58% / **+54.67%** |
| 单笔横截面标准差 | 14.72% |
| P(Y < −20%) / P(Y > +20%) | 0.74% / 6.65% |

**（本轮实测）随机在全市场挑一只票，单笔算术收益是正的（+0.67%），但几何复利收益是负的（−0.32%）。**

这直接解释了 TURN5 报告里那个看似矛盾的现象：为什么随机对照 200 次的中位数是 **−18.27%**（引用 TURN5 报告），而我的逐笔算术均值是 +0.67%——**因为全仓单只 + 仅 40 笔的复利是几何的，不是算术的。**

→ **这就是 objective (e)「先活下来」的定量依据**：单票全仓下，**降低左尾的价值 ≈ 提高均值的价值**。用 `log` 形态做学习目标/损失函数，天然把"−83% 这种灾难笔"的惩罚放大，而不是像 MSE 那样被一个大右尾盖过去。

> ⚠️ 严谨边界：**在"完美预测器"层面，`log` 是 `Y` 的单调变换，两者排序完全相同，捕获率也一样。** `log` 的价值在于**拟合/学习阶段**（对含噪模型、对异常值稳健），不在于改变理论上限。请勿据此宣称"换 log 能提升收益"。

## B. 流动性硬前置 + 退市股边界

### B-0 先纠正一个认知：**现有的失败不是"没有流动性门槛"，而是"门槛没挂在正确的位置 + 门槛被数据源废掉"**

我实读发现，项目里**已经存在**流动性硬前置，而且不止一处：

| 位置 | 内容 | 挂在哪条路径 |
|---|---|---|
| `integrated_picker.py:302-305` | `LIQUIDITY_MIN_AMT = 30_000_000`（近20日均额 ≥3000万）、`LIQUIDITY_MIN_PRICE = 5.0`、`LIQUIDITY_LOOKBACK = 20`、`MIN_LIQUIDITY_LOOKBACK = 60` | **仅实盘出票**（调用点 `integrated_picker.py:562`、`integrated_picker/pipeline.py:225`） |
| `integrated_picker.py:331-360` | `apply_tradability_filter`：流动性 + 价格 + ST + 停牌（volume=0）+ 主板白名单 + 次新 + ATR | 同上 |
| `layers/l1_tradability.py:8-11, 35-67` | 同一套阈值的**已提取层**（ docstring 明写「从 integrated_picker.py 提取」） | 尚未接主线（符合铁律1，应复用它） |

**而 `backtest_rotation.py` / `pick_candidates` 完全没有调用 `apply_tradability_filter`（全仓 `apply_tradability_filter` 的调用点仅上述两处，已 grep 确认）。**

→ **缺陷 ①（结构性）：回测/验证空间 ≠ 实盘可买空间。**
回测在一个"实盘不可达"的候选空间里优化和验收，选出来的信号到了实盘会被 `apply_tradability_filter` 砍掉或替换。TURN5 回测能选出 ADV20 中位 1712 万、41% 低于 500 万、最差 17 万成交额的票（引用 TURN5 报告），**正是因为回测路径根本没有这道筛**。

### B-1 缺陷 ②（数据源把门槛废掉）—— 本次最重要的机制性发现

而 `amount` 在扩展库 `data/history_daily` 62.67% 损坏，坏值恒为 ≈1.27e9 常数（引用主理人实测 + TURN5 报告 BUG-1）。

### B-6 滑点模型改进

**现状（实读）**：
- `backtest_rotation.py:62`：`SLIPPAGE_RATE = 0.001`（0.1%，双边）
- **`:60-61` 注释自承**：`滑点: 全仓单只策略，冲击成本约0.1%（日均成交>5亿股票）` / `小市值股冲击成本可达0.3%，此处用保守估计0.1%`
- `backtest.py:93`：`SLIPPAGE_RATE = 0.0005` —— **另一套引擎是另一个值**（0.05%），两套口径并存

**问题**：0.1% 是个**常数，不随个股流动性变化**。它只对「日均成交 >5 亿」的股票成立（自身注释的原始口径），而我们实际选出来的票远低于这个量级：

- 一手反例：`sh600421` 买入日成交额 **17 万元**，回测照样只扣 0.1% 滑点（引用 TURN5 报告 C-4/C-6）
- 后果：**回测对冷门票系统性低估成本，真实结果只会比 −88.72% 更差**（引用 TURN5 报告）

**改进方案：把滑点改为「参与率驱动的平方根冲击模型」**

```
participation  = order_value / ADV20            # 本单占当日成交额比例
impact_factor = k * sqrt(participation / target_pov)      # 平方根冲击（平方-root law，做市/算法交易通行）
slippage_bps  = clamp(base_bps + impact_factor, floor=base_bps, cap=max_bps)
```

推荐参数（`k`、`target_pov` 用很保守的值，先修"必须随流动性变化"这个结构性错误，不追求精确标定）：

| 参数 | 建议值 | 依据 |
|---|---|---|
| `base_bps` | 10 bp（=0.1%） | **沿用现状**，使大盘股行为零变化 |
| `target_pov` | 1% | TURN5 报告 C-4 采用的「≤1% 冲击可忽略」分档 |
| `k` | 20 bp | 使 pov=1% → 30bp；pov=5% → 55bp；pov=14.91%（退市华嵘那笔）→ ≈87bp（约 0.87%，接近 `:61` 注释说的"小市值可达 0.3%"的保守上沿，且不至于失控） |
| `cap` | 300 bp（3%） | 防止极端 pov 使回测失真到不可用 |
| 单边计入 | 买、卖各计一次 | 与 `buy_cost:153` / `sell_proceeds:161` 现有双边结构一致 |

**效果自查（应当满足的二值判据）**：
1. ADV20 = 5 亿的票、本金 2.5 万 → pov=0.005% → 滑点 ≈ base_bps 10bp → **与现状完全一致（零行为变化）** ✅
2. 退市华嵘那笔（ADV 17 万、本金 2.5 万 → pov≈14.7%）→ 滑点 ≈ 0.87% 双边 → 该笔回测亏损从 −83.33% 恶化到约 −85%，**与"真实只会更差"的定性判断同向** ✅

> 另需并行处理：`backtest.py:93`（0.0005）与 `backtest_rotation.py:62`（0.001）两值并存，属**契约漂移**，应在同一批次收敛为同一函数（推荐以 `backtest_rotation` 为唯一实现，`backtest.py` 反向引用）。

## C. 验证协议（含命令与阈值）

### C-0 设计原则：把「一次性复利终值」换成「逐扫描日配对检验」

TURN5 报告最有价值的资产是随机对照，但它有一个结构性弱点（我必须指出）：

> **现有 C 系列判据比的是「策略最终那条复利曲线 vs 200 次随机终值」，样本量 = 1 个数字。**
> 而全仓单票只产生 36~44 笔交易，随机终值分布极宽（min −89.83%、p95 +258.55%、max +1149.22%）。**用一个点去和一个极宽分布比，统计功效很低**——这既会让烂信号偶尔蒙对（False Positive），也会让还行的信号被误杀（False Negative）。

**升级（本方案新增）：把比较粒度从"策略级终值"降到"扫描日级配对差额"。**

对每个扫描日 `d`，因为**同一天的市场环境对所有候选是共同的**，可以做配对做差，把市场 beta 差分掉：

```
Δ_d = u(被选中的那只)  −  mean_{c ∈ 候选池_d} u(c)
u(Y) = log(1 + Y_barrier/100)
```

- 样本量从 1 变成 **242**（全窗口扫描日数）
- 且 `Δ` 消除了"这段时间大盘好不好"的干扰 → 检验聚焦在**选股本身的增量**
- **可直接复用现成的 `factor_gate_v2.newey_west_t`**（`scripts/factor_ic_132d_refresh.py:63` 已在引用，符号 (`c,o,h,l,v,a`) 且一 AST evidence 口径一致）
- NW 修正是必需的：相邻扫描日的 barrier 窗口互相重叠（同 A-5 的 lag 问题），lag 取 20（覆盖一个月的重叠）

> 这是本方案在方法论上唯一"新增"的东西，其余全部复用现有基建。

## D. 方案骨架与落地路径

### D-1 选股信号怎么组织：**不再是「多因子线性加权」，改成「硬过滤 + 单目标监督」**

**论证（为什么单票全仓不需要多因子加权）：**

1. **多因子加权是为组合设计的。** 组合里你有 N 个仓位，每个因子的 alpha 各取一点，**平均**带来稳定的边际改进。**全仓 1 只时你只交易排第 1 的那一个**——此时"对全体平均最优"和"对第 1 名最优"是两回事，而且 TURN5 已经用实证给过反例：它在横截面平均意义上站得住（NW-ICIR −0.3568，全 28 因子 |IC| 最大），但在第 1 名上灾难性失败（引用主理人实测 + TURN5 报告 D-3）。
2. **加权天然把信号"平均化"，而平均会削弱极端分位的判别力。** 我们要的正是极端分位。
3. **现状其实已经证明这条路走不通**（实读确认）：`config.json` 的 `factor_weights` 只有 `LOWER_SHADOW=0.15` 非零，而 `tdx_indicators.compute_indicators` 返回的 **66 个键里根本没有 `LOWER_SHADOW`**（我跨 **282 只股票**取键集合并集验证，确为 66 个且不含它）→ **因子分恒为 0，score 实际退化为「技术分」**，且不报错。**主理人这条观察完全成立。**

**推荐骨架（三层，全部调用现有能力）：**

```
┌─ L0  Universe   BT.collect_all_stocks() + BT.is_st_stock(=is_st_only)      # 含退市股，R9 不动
├─ L1  Tradability layers/l1_tradability.apply_tradability_filter(...)        # 逐日硬前置, 复用
│      + tdx_data.is_st_stock (含"退")                                        # 复用
│      + B4 amount 一致性校验                                                 # 新增(小)
└─ L2  Score      target = barrier 对数收益 log(1+Y_barrier)                  # 单一目标
                  模型形式: 首选可解释的浅层模型/规则; 若用 ML 也只输出一个标量
                  严禁: 多因子线性加权再求和
```

- **不看 Occam 面就用 ML**：首选「少数几个**互相去相关**的特征 + 浅模型」，且去相关判据复用现有口径（相关执行官。简单 Pioneer —— 先用现有 `tdx_indicators` 的 66 键做特征池即可，**不要新建第二套因子实现**）
