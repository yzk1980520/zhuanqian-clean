## 三、为什么剩下 4 个改不动（根因实证）

```
Register-ScheduledTask : 拒绝访问。
FullyQualifiedErrorId  : HRESULT 0x80070005,Register-ScheduledTask
```

**不是 XML 有问题**——实证：把 `QSP_PreMarket` 的 XML **原样不动**再灌回去，同样报 `0x80070005`；
而同样操作对 `QSP_DrainWatch` 成功。说明是权限，不是定义。

**根因**：

```
当前会话权限（实测）
  USER=WIN10  TOKEN_ADMIN=False
  组：Users / Everyone / docker-users / INTERACTIVE / ...   ← 没有 Administrators

任务文件属主（实测 C:\Windows\System32\Tasks\）
  QSP_PreMarket            Owner=BUILTIN\Administrators   ← 标准账户改不了
  QSP_ZLJWatch             Owner=BUILTIN\Administrators   ← 标准账户改不了
  Zhuanqian_DailyAuto      Owner=BUILTIN\Administrators   ← 标准账户改不了
  Zhuanqian_BoardWatchdog  Owner=DESKTOP-THU5BUJ\WIN10    ← 但仍被拒（注册表 TaskCache 侧同样受限）
  QSP_DrainWatch           Owner=DESKTOP-THU5BUJ\WIN10    ← 成功，作为对照
```

WIN10 是**标准账户**（token 里连 denied-only Administrators 都没有），所以：

1. 不能自提权 —— UAC 提权必须有管理员凭据交互，而**弹 UAC 到老大桌面本身就是违反本次静默要求**，
   因此我没有、也不会自动触发提权。
2. 不能靠"新建同名替身任务绕过" —— 老任务 `Disable-ScheduledTask` 同样会被拒，
   留着不动就是每天重复跑两次。

**已备好提权脚本**（我这边跑不了，等老大/管理员执行）：

```powershell
# 「以管理员身份运行」的 PowerShell 里执行：
powershell -ExecutionPolicy Bypass -File scripts\w3_silence_remaining4_elevated.ps1          # 先看计划
powershell -ExecutionPolicy Bypass -File scripts\w3_silence_remaining4_elevated.ps1 -Apply   # 确认后执行
```

脚本自带提权检查，未提权时会明确提示并 `exit 1`，不会静默空转。

## 四、代码层弹窗源审计

### 4.1 为什么代码层也要改

`pythonw.exe` **没有控制台**。它 spawn 的任何 Console 子进程会被 Windows **分配一个新的可见控制台** ——
桌面黑框一闪。所以铁律 3（改用 pythonw）必须配铁律 4（CREATE_NO_WINDOW），不然反而更糟。

### 4.2 全仓扫描结果

初始状态：**124 个文件 / 187 处**派生子进程却没带 `CREATE_NO_WINDOW`。

**处置口径**（按交办要求）：**只改会被计划任务定时触发的路径**，交互调试脚本不动
（动了就看不到输出，比弹窗更糟）。反向梳理「22 个计划任务 → 入口脚本 → 调用链」后，
落在 leaf 上的待修集合是 **11 个文件 / 25 处**：

| 文件 | 处数 | 所属计划任务 | 说明 |
|---|---|---|---|
| `scripts/self_heal_check.py` | 5 | QSP_SelfHeal | `schtasks` ×4（query/run/change）+ `cmd rmdir` ×1 |
| `scripts/sys_watchdog.py` | 5 | QSP_SysWatchdog | `schtasks` ×2 + `git` ×3 |
| `scripts/loop_watch.py` | 3 | QSP_LoopWatch | `schtasks` query/run/change |
| `scripts/git_sync_task.py` | 2 | QSP_GitSync | `git` + `pytest` |
| `orchestrator.py` | 2 | Zhuanqian_DailyAuto（经 automation_scheduler 调用） | `risk_monitor.py` + `backtest.py` |
| `scripts/auto_pipeline.py` | 2 | Zhuanqian_Rotation132d | `Popen` 起回测 + 起 `python.exe` 刷 flags |
| `run_sanity_gate_cron.py` | 1 | Zhuanqian_SanityGate(_Night) | `check_backtest_sanity.py` |
| `scripts/system_health_check.py` | 1 | Zhuanqian_DailyAuto（间接） | `shell=True` 跑 git 等命令 |
| `scripts/check_remote_main_freshness.py` | 1 | QSP_RemoteFreshness | `git` |
| `scripts/automation_scheduler.py` | 1 | Zhuanqian_DailyAuto | 起 `orchestrator.py` |
| `cron_message_sender.py` | 1 | QSP_MsgDrain | `lark-cli.cmd` |

改法统一：

```python
CREATE_NO_WINDOW = getattr(subprocess, "CREATE_NO_WINDOW", 0)   # 非 Windows 回落 0
subprocess.run([...], ..., creationflags=CREATE_NO_WINDOW)
```

`getattr(..., 0)` 保证同一份代码在 Linux/macOS 上照跑，不需要平台分支。

**验证**：改后复扫，以上 11 个文件在 `audit_popup_sources.py` 结果里**全部消失**（0 命中）；
10 个文件通过 `py_compile`，6 个可安全 import 的模块实测 `CREATE_NO_WINDOW=134217728`（= 0x08000000）。

### 4.3 判定「可不管」的部分及理由

剩余 **113 个文件 / 164 处**未改，分类理由：

| 类别 | 处数（约） | 为什么不改 |
|---|---|---|
| `.trash/`（20261015、20261016 清出来的死代码快照） | 41 | 已隔离、不参与任何定时触发；改它就是"改历史存档" |
| 一次性/研究/诊断脚本（`scripts/backtest_diagnose.py`、`scripts/full_system_diagnosis.py`、`scripts/worktree_regression.py` 等） | ~90 | 交互使用，老大要盯着输出跑；静默化 = 失去调试可见性 |
| 看板/GUI 服务器（`dashboards/board_server.py`、`start_warroom_server.py`） | 3 | 本来就是要在前台起服务给人看的（且用 `pythonw.exe`，常态无窗） |
| 网关守护类（`scripts/gateway_guardian.py`、`hermes_health.py`） | ~4 | **Hermes 网关归老大/总管管**，且铁律明确禁止我启停 daemon；不在本次授权范围 |
| `.quant-stock-picker\scheduler\watchdog.py` / `watch_zlj_backtest.py` / `gateway_health_check_opt001.py` | 5 | **在 files ownership 清单之外**（不在 repo 里）。且它们由 `run_qsp_hidden.vbs` 起在一棵隐藏控制台里，子进程继承同一个隐藏控制台 —— 现状不弹窗。**但如果哪天有人把它们改成 pythonw，这 5 处会立刻变成新弹窗源**，已写进规范文档第 3 节注意事项 |

> 一句话口径：**不是所有 `subprocess` 都是弹窗源，只有当它跑在一个「没有控制台的宿主」里时才是。**
> 所以标准不是"全改"，而是"改那些确实活在计划任务链条上的"。
