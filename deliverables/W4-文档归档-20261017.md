#### 2.3.2 路径解析写法共识（W5 提议，双方采纳，立为长期规则）

> **本仓库根目录叫 `open code`（含空格），任何按空白分词的路径解析都会踩坑。**
> 以后写扫描器优先用「**先匹配完整路径串、再 `strip_root()`**」，
> 而不是「先 token 化、再找 `.py` / `.md` 后缀」。

修正后的 `ABS_MD` 就是前一种写法。后一种写法的失效模式有两种，风险不对等：

| 写法 | 遇到含空格路径 | 失效方向 | 危害 |
|---|---|---|---|
| 先 token 化再找后缀 | 在空格处截断 | **误归属 / 误报** | 高 —— 把成本记错科目，结论失真 |
| 先匹配完整串再 strip_root | 能整体取出 | 漏匹配（假阴性） | 低 —— 只少扫，不错判 |

**结论：宁可漏，不可错。** 扫描器的价值在于给出可信的判定，漏一条可以后补，
错一条会让人照着错的结论去改文档。

**W5 侧同类风险核查结论（已交叉验证，无遗留）**

| 位置 | 写法 | 空格风险 | 结论 |
|---|---|---|---|
| `tests/test_no_phantom_script_refs.py` | `RE_SCRIPT = scripts/[A-Za-z0-9_\-]+\.py` | 不允许空格 → 漏匹配 | 仓库内脚本名均不含空格，**当前无漏网** |
| `scripts/build_bak_index.py` | `.bak` 反解用 `.+?` 非贪婪 | 能吃空格 | 不受影响 |
| W5 全量幽灵核查的一次性扫描 | 字符集排除空格 | 漏匹配 | **8 个幽灵入口均已先确认文件确实不存在**，无误归属 |

### 4.1 修复：`--only` 查已还原文件会误报"没匹配"

**问题**：`--only` 默认只在「待还原」条目里搜。那 19 个已还原回原位的文件，
用它查会返回 `No entry matched. Aborting.`（exit=1）。

W5 已把这条命令写进 `BOOTSTRAP.md` §四（回滚节）作为自助入口，
于是这个行为就变成了陷阱：任何人查这 19 个文件都会得到"没匹配到"，
很可能被读成**文件丢了**，然后来问我要还原 —— 而文件本来就在原位。

**修复**（`scripts/restore_archived_docs.py`）：`--only` 无命中时，
回过头在已还原条目里再查一次，命中就明确告知并 exit=0：

```python
if not chosen:
    already = select([e for e in all_entries if e.get("status") == "restored"],
                     args.only)
    if already:
        print("\n[ALREADY RESTORED] %d 条命中，但这些文件**已经还原回原位**了：" % len(already))
        ...
        return 0
    print("No entry matched. Aborting.")
    return 1
```

**顺带改进**：`--list` 原来只列待还原的 663 条，现在列全部 682 条并标注
`[ARCHIVED]` / `[RESTORED]` —— 查文件的人首先需要知道的是
「它是不是已经还原过了」。

#### 扫描器修正说明（影响数字口径，必须留痕）

上一版扫描把看板快照的 43 处引用判成了 **T2「历史遗留错链」**，这是**错的**。

于是被误判为"与归档无关"。

修正方式（`scripts/scan_archived_links.py`）：

```python
ABS_MD = re.compile(r"(?:file:///|[A-Za-z]:[\\/])[^\r\n\"'`|<>]*?\.md", re.IGNORECASE)
```

先用专用模式整体取出绝对路径 / `file://` 引用，其 span 从通用扫描中排除（避免重复计数），
再走 `strip_root()` 去掉根前缀。

1. **重复计入、放大噪声**（已确认）。`.worktrees/t_d0ed25cc/` 是完整文档镜像，检索时同一个冲突/同一段话会被命中两次以上，直接污染"冲突计数""覆盖率"这类统计口径。
