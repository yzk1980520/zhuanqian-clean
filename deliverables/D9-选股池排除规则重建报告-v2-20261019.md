## 二、实现方式与 spec 的一处关键分歧（必须老大知悉）

### spec 要求 vs 实际实现

spec 说"三样都加在 `collect_all_stocks()`"，仅对价格/ADV 开了"数据不可得就放加载后筛选点"的口子。
**实现把三项全部做成「逐扫描日」过滤，挂在 `backtest_rotation.py` 的 `pick_candidates()` 里
（截面百分位之前），没有放进 `collect_all_stocks()`，也没有在加载段整只剔除。**

### 为什么（不是任性，是硬约束 #1 逼的）

先看实测数据（`stock_names.json` + TDX 目录 + 扩展库，脚本实数）：

| 分类（按名称表最终名称快照） | 只数 |
|---|---|
| 扩展库独家（TDX 已删，含退市） | 157 |
| ├ 其中 ST/*ST 前缀（加载段已剔，66） | 66 |
| ├ 其中**名称含"退"**（退市金钰/大通退…） | **77** |
| └ 其中名称干净（当时没戴帽、后来才退市） | **14** |
| TDX 当前上市但名称含"退"（退市整理期中） | 10 |

关键事实：**157 只独家票里 77 只的最终名称含"退"**。当前审计口径
`with_data_count = 157 − 66 = 91`，其中 77 只是"退市XXX"/"XXX退"。

- 若按 spec 字面放在 `collect_all_stocks()` 按最终名称整只剔除 → 77 只连同它们
  **数年正常交易历史**一起被删 → `with_data` 91→14，"当时没戴帽、后来才退市"的票
  被删光 → **正是硬约束 #1 明文禁止的"按后来是否退市剔除"（前视偏差，逆转 R9）**，
  且 R9 地板（91）当场爆红。
- 名称表只有**最终名称快照**（无逐日名称），"当时名称含退"这个状态在数据层只能
  近似为：**该票最后 30 根 K 线 = 退市整理期窗口**（A 股标准 30 个交易日）。
  窗口内的扫描日禁买（当时名称已含"退"）；窗口外保留候选资格（当时未戴帽）。

价格/ADV 同理：是逐 bar 量，按最终价/最终流动性整只剔除 = 用 2025 年的状态删 2021 年的候选。

### 与实盘的口径对齐

实盘 `integrated_picker.apply_tradability_filter` 在**评分前**过滤（:562，先于
compute_indicators/截面百分位）。回测侧同序：过滤挂在 `pick_candidates` 截面百分位
**之前**，阈值完全一致（价格 5.0 / 近 20 日均额 3000 万），常量在
`backtest_rotation.py` 模块级重新声明并注明"与 integrated_picker.py:302-303 同口径，
禁止回测侧自降门槛"（未 import integrated_picker：该包/模块存在同名遮蔽且依赖重）。
