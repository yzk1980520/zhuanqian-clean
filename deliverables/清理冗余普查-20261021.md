## 〇、普查方法与扫描范围声明（硬约束 2 的执行说明）

全仓 `grep -rn` 会因 `backups/` 下损坏路径触发 SIGTERM（实测：`du -sh .` 整仓测量 120s 即被 SIGTERM），因此**所有"是否被引用"的结论均来自以下限定范围的定向扫描，不是全仓扫描**：

| 扫描范围 | 命令形态 |
|---|---|
| 根目录 `*.py` | `grep -ln "<关键词>" *.py` |
| scripts/ | `grep -rn "<关键词>" scripts/` |
| .agent/ | `grep -rln "<关键词>" .agent/` |
| mainline/ | `grep -rln "<关键词>" mainline/` |
| agents/、team/ | `grep -rln "<关键词>" agents/ team/` |
| tests/、cron/、config/ | `grep -rn "<关键词>" tests/ cron/ config/` |
| 调度层 | `grep -n "<关键词>" cron_config.json config.json` + `grep -rln "<关键词>" scripts/*.cmd scripts/*.bat scripts/*.xml scripts/*.vbs` + `grep -ln "<关键词>" *.bat *.ps1` |

**判定"活跃引用"时排除的非活跃区**：`backups/`、`_archive/`、`research_archive/`、`.worktrees/`。这些区域里出现同名/引用不代表活跃代码在用（例：`.worktrees/t_d0ed25cc/research_archive/skill_router.py` 引用 `_refresh_trading_calendar.py`，但主工作区有更强证据，见 C 档）。

## 五、最建议先清的 Top 3 及理由

1. **A 档全套（数字目录 + aipy laoliu + %s + 0 字节垃圾 + 根一次性 `_*`，≈44.5 MB / 98 个文件）**
   理由：唯一零争议区块——活跃区全范围定向扫描 0 引用（连仓库自己的审计工具都把它们列进 SKIP_DIRS），与选股/实盘/门禁/调度无任何交集，tracked 部分删了历史可溯。唯一动作前置：跟老四确认一句 AiPy 会话已收工（`16/` `14/` 是最新两个）。
2. **`.scratch/` untrack + `.gitignore` 补 `.scratch/`（B1，≈7.5 MB + 防复发）**
   理由：目录是生产日志 Target 不能删，但 131 个 tracked 历史产物是扫荡事故；amount 取证所属任务 #8/#11 均已 completed，结案风险低。这是**防复发**价值最高的一刀（.gitignore 无 .scratch 条目，下次 `git add -A` 还会卷土重来）。
3. **`backups/` untrack 决策（C8 关联，`.git` 5.1G → 新克隆 ≈1.9G）**
   理由：`.git` 66.3% 是这一个目录，.gitignore 无条目=定时炸弹。但 3.2G 是 P0 amount 修复前唯一全量快照，**删磁盘文件=越 C 档红线**；正解是"文件留盘、退出版本控制"（`git rm -r --cached backups/` + ignore），须老大拍板保管位置（原地/迁移动硬盘/转压缩归档）。建议与任务#50（protect-archive-wip）同等级谨慎处理。
